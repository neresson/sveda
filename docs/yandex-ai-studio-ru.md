# DeepSeek V4.1 Flash в Yandex AI Studio для Sveda LMS

Профиль `yandex-ru` закрепляет генерацию текста в LMS и Sveda runtime за одним адресом — `https://ai.api.cloud.yandex.net/v1/responses`. В каталоге Яндекса доступна DeepSeek V4.1 Flash. Яндекс указывает, что разместил эту модель на серверах в России. Прежний код LMS использует псевдоним `deepseek-flash`. Совпадение версии весов, параметров обслуживания, скорости и ответов у двух операторов требует отдельного подтверждения. [Каталог моделей](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) · [Размещение модели](https://yandex.cloud/ru-kz/blog/digest-scale-2026)

## Подготовка стенда

1. Создайте каталог Yandex Cloud с активным платёжным аккаунтом. Выдайте сервисному аккаунту роль `ai.languageModels.user` на каталог и API-ключ с областью `yc.ai.foundationModels.execute`. Согласуйте условия обработки, регион инфраструктуры, объём, тариф и квоты. Отдельные ключи для PHP и runtime позволяют отзывать доступ независимо. [Пример и права доступа](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/create-prompt)
2. Соберите **оба** проекта из ревизий с этим профилем. Разместите тестовый runtime, его PostgreSQL, Redis, прокси, историю, резервные копии и саму LMS на согласованной инфраструктуре в РФ. Если текущее размещение сервера `runtime.sveda.dev` документально не подтверждено, используйте отдельный российский экземпляр. Один профиль применяется ко всем посетителям экземпляра.
3. Передайте настройки ниже каждому процессу `sveda-server`, а также Laravel web, очередям и планировщику через секреты среды. Для Laravel установите ещё `YANDEX_AI_OCR_ENABLED=false` до отдельного решения по OCR. В приложении направьте `SVEDA_CLIENT_BASE_URL` и `VEDA_SIDECAR_URL` на утверждённый экземпляр. Проверьте URL, TLS и авторизацию обратного соединения host MCP. В Docker Compose из этого репозитория три переменные уже перечислены для сервиса `sveda-server`; используйте образ, собранный из новой ревизии.

```dotenv
SVEDA_INFERENCE_PROFILE=yandex-ru
SVEDA_YANDEX_FOLDER_ID=<идентификатор каталога>
SVEDA_YANDEX_API_KEY=<секрет сервисного аккаунта>
```

4. После изменения окружения соберите кеш конфигурации Laravel заново (`php artisan config:cache`) и перезапустите web-процессы, очереди и runtime. На стенде уберите прямые ключи DeepSeek/OpenAI из процессов. Ограничьте исходящие соединения разрешёнными российскими адресами модели, собственных сервисов и инструментов. В настройках каталога Yandex AI Studio проверьте, что трейсинг в Monium отключён. Если требуется общая настройка облака, Яндекс принимает запрос об отключении логирования через поддержку. [Политика хранения](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage)
5. Используйте синтетические примеры до решения о выпуске. Проверьте ответ и потоковый вывод в LMS, повторный вопрос с контекстом, режим рассуждений, вызов разрешённой локальной функции с продолжением после её результата и генерацию структурированного урока. В метаданных исходящих соединений проверьте только разрешённые адреса. Используйте отдельный ключ тестового каталога для проверки реальной модели — такие запросы тарифицируются. Сверьте учёт токенов, квоты и внутреннюю тарификацию LMS с договором. При отказе Yandex запрос завершается ошибкой. Для остановки отключите ИИ или вернитесь на последнюю версию с подтверждённым российским маршрутом.

## Что отправляется

| Канал | Поведение в профиле |
| --- | --- |
| Чат, сокращение истории и повторные обращения к модели | Runtime выбирает `gpt://<каталог>/deepseek-v4.1-flash` независимо от сохранённого списка провайдеров, прямого ключа и запасных моделей. Клиент передаёт историю, инструкции, доступные функции и их результаты в пределах обычного контекста. |
| Внутренние задачи Laravel | Вызовы Laravel AI SDK, включая заголовок чата, генерацию курса, урока, списков и материалов базы знаний, используют тот же Responses API. Сохранённое имя провайдера или явно заданная старая модель также проходят через этот маршрут. |
| Настройки хранения | Каждый запрос генерации содержит `x-data-logging-enabled: false` и `store: false`. Первый параметр управляет использованием запросов для улучшения сервиса. Второй отключает хранение объекта ответа для последующего обращения. Историю между ходами собирает сама Sveda. Служебные и аудитные логи Яндекса сохраняют метаданные; отдельно включённый трейсинг может записывать содержимое. В собственной инфраструктуре применяются настройки хранения и доступа LMS, прокси и резервных копий. [Отключение логирования](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging) · [Политика хранения](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage) |
| Инструменты и веб | Локальные функции и host MCP LMS остаются доступны согласно полномочиям пользователя. Результаты возвращаются в контекст модели. Встроенный интернет-поиск и загрузка веб-страниц runtime выключены. Подключённые MCP-серверы, браузерные инструменты и интеграции LMS могут обращаться к своим адресам. Уберите внешние подключения либо согласуйте каждого получателя, поля и место обработки. |
| Эмбеддинги и поиск | Сетевые эмбеддинги отключены и в runtime, и в PHP. Часть поиска runtime использует локальное хеширование, операции LMS, требующие новых векторов, недоступны. Существующие индексы и векторы сохраняются. Семантический поиск на новом российском embedding-провайдере потребует отдельной модели, проверки размерности и переиндексации. |
| Документы | Rust-обработчик принимает поддерживаемый UTF-8-текст. LMS разбирает также офисные документы и PDF, извлечённый текст может попадать в запрос модели. `YANDEX_AI_OCR_ENABLED=false` отключает самостоятельный канал отправки изображений и PDF в Vision OCR, включая случаи, когда задан общий ключ. Возможность распознавания сканов зависит от локальных средств. Проверьте регион файлового хранилища и доступ по ссылкам. API Files, Conversations и векторные хранилища AI Studio здесь не требуются. Включение этих API создаёт ресурсы с отдельными сроками хранения. |

## Локальное воспроизведение

Команды используют подменённые HTTP-ответы или loopback. В PHP-тесте вызов устаревшего провайдера проходит через обычный SDK, проверяются выбранный URL, модель, заголовки, отсутствие запасного запроса и выключенные эмбеддинги.

```sh
# sveda-ai/sveda, при уже загруженных зависимостях
cargo test --locked --offline -p sveda-llm -p sveda-server --lib

# scorpiolms
php vendor/bin/phpunit tests/Feature/YandexInferenceProfileTest.php
```

Локальные тесты подтверждают состав запросов и выбор маршрута. Доступность API для конкретного договора, квоты, задержки, поддержка схем ваших инструментов и фактическое размещение собственных компонентов проверяются при приёмке стенда. Переключение затрагивает последующие обращения; у прежнего провайдера ранее отправленные данные регулируются его условиями и договорённостями.
